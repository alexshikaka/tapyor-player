# AGENTS.md — правила для любой модели

Этот файл — универсальная точка входа для любой нейросети (Codex, Cursor, Gemini, DeepSeek, Claude и другие). Если ты продолжаешь проект «Тапёр» — начни здесь.

## Порядок входа

1. `docs/START-HERE.md` — что это за проект и что читать.
2. `docs/CURRENT.md` — где остановились.
3. `docs/HANDOFF.md` — состояние и карта кода.
4. `docs/DEV.md` — как запустить на ПК владельца.
5. `docs/DECISIONS.md`, `docs/ERRORS.md` — почему так и где грабли.
6. Для аудита — `docs/AUDIT.md`; для релиза — `docs/RELEASE-CHECKLIST.md`.

## Жёсткие правила

- Работаем локально. Публикация на GitHub — только по явной команде владельца.
- Версию и `appId` без команды не менять.
- На GitHub есть только main (релиз и документы). Рабочая ветка experiment живёт локально у владельца; если её нет в клоне — работай в main.
- Скины только «красят»: раскладку и поведение не менять.
- Владелец не программист: объяснять простыми словами, показывать скриншоты и замеры.
- Секреты не хранить в файлах; не публиковать значения ключей.

## В конце каждой сессии — обязательно

1. Обновить `docs/CURRENT.md` — что сделано, что дальше.
2. Добавить карточку `docs/sessions/ГГГГ-ММ-ДД-модель.md`.
3. Дописать `TODO.md`; решения и ошибки — в `docs/DECISIONS.md` и `docs/ERRORS.md`.
4. Если менялся запуск — `docs/DEV.md`.
5. Переписку сдать: краткую — в `history/COMPACT.md`, полную — в архив/ассеты.

Сессия не считается законченной, пока нет карточки и обновлённого `CURRENT.md`.

## Релиз

Только по фразе «собери релиз на гитхаб». Выполнить `docs/RELEASE-CHECKLIST.md` целиком и без напоминаний, затем `node tools/release-preflight.mjs <версия>`. Если чек-лист не выполнен — сказать прямо, что релиз не готов, и не публиковать.

## Если ты не умеешь читать репозиторий

Попроси владельца дать архив `tapyor-audit-pack` или локальную папку `C:\tapyor-player`. Содержание то же.
