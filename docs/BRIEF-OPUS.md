- Работаем **локально** в `C:\tapyor-player`. «Собери» = собрать/запустить локально, не публиковать.
- GitHub-релиз — **только по явной команде**. Версия сейчас **0.19.0**, релиз 0.19.1 отложен.
- Ветка текущей работы — **`experiment`**; `main` — релизная. Теги: `v0.17.1`, `v0.18.0`, `v0.19.0`, плюс `backup-before-work-21oct`.

- Подвал и шапка — фиксированные зоны; прокручивается только список очереди.

## 2. Что за программа

«Тапёр» — Electron-плеер для стримеров: поиск и проигрывание музыки (Яндекс, YouTube, SoundCloud, Audius, Telegram), очередь-лента за день, «Моя волна», плейлисты, заказы песни за донаты (DonationAlerts, DonatePay, Donatello), панель для OBS, самопроверка сервисов, автообновление.

Стек: Electron 33 (Chromium 130), один `BrowserWindow` с `src/index.html` (вся вёрстка, CSS и JS в одном файле), `src/main.js` — окна, IPC, сервер, интеграции; `src/preload.js` — мост `window.app` (в коде — `A`). Сборка — electron-builder, установщик NSIS.

Есть второй, отдельный проект **«Тапёр лайт»** на WPF (`C:\tapyor-light`) — переписывание на C#; он не входит в этот аудит, но скриншоты для отчётов складываются в его `docs`.

## 4. Что делалось 23.10.2026 (последняя сессия)

Цель — доводка мелочей интерфейса; всё локально, без релиза.

1. **Шапка.** «Масштаб N%» слева от версии, без иконки. Единое правило для группы масштаб/версия/обновление: высота 20, шрифт 11, радиус 5, паддинг 0 8 — проверено на всех оболочках. Кнопка «Обновить» — та же группа, но с заливкой акцентом.
2. **Подсказки.** Были нативные `title` и один themed `data-tip`. Сделали единый `.tip`: один fixed-элемент, задержка 600 мс, одна строка, автопереворот у кромок; у перемотки — отдельный, следует за курсором. По пути выяснилось, что `[data-tip] { position: relative }` ломал подвал (абсолютные дети получали другого родителя) — правило убрали.
3. **Окно масштаба — главная сага.** Сначала поповер в странице; он масштабировался вместе с интерфейсом и дёргался. Вынесли в отдельный `BrowserWindow` (`src/zoom.html` + `src/zoom-preload.js`), 300×208, всегда 100 %, кнопки 60–140 с шагом 10 % и ползунок, тема из плеера (цвета, шрифт, радиусы), скрытие по фокусу/ Esc. Борьба с миганием прошла через: `scale(1/zoom)`, «тема до показа», сжатый чекпойнт, ожидание `zoom-ready`, тему в адресе (`?t=base64`), синхронизацию темы со скрытым окном, перезагрузку скрытого окна. Итог: окно **пересоздаётся при каждом открытии** с темой в адресе, показывается после `ready-to-show` с `opacity 0→1` за 80 мс, повторный клик закрывает. Это убрало мигание.
4. **Заказы.** Убраны свечение и мигание кнопки; плавно светится только цифра счётчика (`badgeGlow`, 3.2 с), при `prefers-reduced-motion` — статично.
5. **Хотфиксы.** Дважды ломался `main.js` при переписывании окна: пропала `revealZoomWindow` (ошибка в диалоге Electron) и дублировались загрузки страницы. Исправлено, проверено.

Все записи с замерами — в `TODO.md`, первые ~140 строк.

## 6. Как проверяем (без установщика)

1. Убрать `ELECTRON_RUN_AS_NODE`, запустить `node_modules\electron\dist\electron.exe C:\tapyor-player --remote-debugging-port=9222`.
2. Playwright из `C:\tapyor-verify` подключается по CDP `http://127.0.0.1:9222`, находит страницу `index.html`; проверки — через `page.evaluate`, скриншоты `page.screenshot`.
3. Для окна масштаба — отдельная страница `zoom.html`; её можно найти в `context.pages()`.
4. После правок `index.html` обязательно `node --check` последнего `<script>` (иначе синтаксис ломается незаметно).
5. Аудит скинов: `npm run audit:skins` (сейчас 3 оболочки — VGA/DOS, Неон-скан, Ретро-десктоп; 0 ошибок).

## 7. Известные риски и долг (для аудита)

- **Один файл на 7,5 тыс. строк** — главный риск: сложно править, легко сломать, нет модулей и типов.
- **Дублирование состояния**: настройки в `settings.json` и `localStorage` (например, `uiZoom`, тема, схемы), синхронизация вручную.
- **Окно масштаба** прошло 8 итераций; логика в `main.js` + отдельная страница, тема передаётся и событием, и в адресе — стоит проверить на избыточность и гонки.
- **Подсказки**: `title` → `data-tip` конвертируется MutationObserver + `setInterval(1000)` + обработчиком наведения — три механизма на одну задачу.
- **Безопасность IPC**: широкий мост `window.app`; стоит проверить валидацию аргументов и что в renderer нет лишнего доступа.
- **Тесты**: покрытие точечное (reqparse, skins); UI-тесты ручные, харнесс `C:\tapyor-verify` вне репозитория — не воспроизводится у другой машины.
- **Git-история** начинается с 0.17.1: ранние версии только в документах; ветки `main` и `experiment` разошлись — риск при релизе.
- **Скриншоты вне репозитория** — теряются при передаче.
- **Кириллица и пути**: PowerShell + `-Encoding utf8`, ошибки с `$()` в строках; правки по номерам строк уже дважды ломали файл.
- **Скины**: `pixel:false` пока мягкий режим аудита; часть проверок для новых принципов не автоматизирована.

## 8. Задание на аудит (что вернуть)

Проведи полный аудит и верни **один отчёт**:

1. **Краткое резюме** — 5–7 пунктов, что работает хорошо и что критично.
2. **Проблемы по severity** (Critical / High / Medium / Low). Для каждой: файл и строки, в чём риск, чем подтверждается (чтение кода/тест/замер), как воспроизвести.
3. **Архитектура и рефакторинг**: как разумно распилить `index.html` без риска (порядок шагов), где ввести состояние/шину, что вынести в модули; оценка «выгода/риск/время».
4. **Окно масштаба и подсказки** — отдельный разбор: упростить, убрать дубли, гонки, утечки.
5. **Производительность**: размер DOM, частые перерисовки очереди/волны, тяжёлые CSS-анимации, память при долгом стриме.
6. **Скины/темы**: контракт «только покраска», автоматизация аудита, что добавить в проверки.
7. **Надёжность и данные**: настройки, миграции, потери состояния, очередь, восстановление после сбоя.
8. **Безопасность IPC/preload**, обновления, подпись.
9. **Тесты и воспроизводимость**: что покрыть в первую очередь, как вынести харнесс в репозиторий.
10. **План оптимизации**: таблица «шаг / зачем / файлы / риск / когда делать», с очередностью на 3 горизонта (сейчас, после релиза, потом). Явно отдели «быстрые победы» от «крупной перестройки».
11. **Что не делать** — антипаттерны, которые уже пробовали и отвергли (Scorched/Winamp, `[data-tip]` с `position:relative`, `scale(1/zoom)` как основной механизм, скрытое окно со старой темой).

Ограничения аудита: **ничего не публиковать и не менять версию/appId**; не переписывать код без согласования — сначала отчёт и план. Если предлагаешь правку, указывай файл, участок и ожидаемый эффект.
