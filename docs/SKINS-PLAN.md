# План переработки системы скинов — версия 2

Это вторая версия плана. Первую проверил дважды: сначала по коду, потом отдельным ревью «на злобу». Ниже — что оказалось неверным и что предлагается вместо этого. Код пока не менялся.

## 1. Что было не так в первой версии

| Утверждение v1 | Что показала проверка |
|---|---|
| «Скин не трогает раскладку» | Уже сейчас `html.skin-retro .sec-h h2` задаёт `padding: 3px 10px; margin-left: -10px`, а `html.skin-dos …:active` — `transform`. Значит правило нужно не декларировать, а **обеспечивать механизмом** и миграцией существующих правил. |

## 2. Что предлагается (v2)

### 2.1. Скины остаются в одном файле, но по правилам

Полный вынос в отдельные файлы отклонён: `/app.css` для OBS-дока собирается из `index.html`, а `file://` ломает загрузку манифестов. Вместо этого:

- **Вся разметка и данные схем — в `index.html`** (как сейчас).
- **CSS каждой оболочки — отдельный `<style>`-блок с `data-skin-style="<id>"`** внутри того же файла. Это даёт группировку и возможность включать/выключать блоки, не меняя сборку и не ломая док.
- Когда/если понадобится вынести в файлы — отдельным шагом, вместе с правкой `/app.css`, чтобы док получал те же стили.

### 2.2. Каскадные слои вместо `!important`

```css
@layer base, skin, decor;
@layer base { /* всё текущее оформление и компоненты */ }
@layer skin { /* правила оболочек */ }
@layer decor { /* фоновые слои, скан-линии, виньетки */ }
```

- Внутри `@layer skin` правило оболочки выигрывает у базового **без** `!important` — специфичность больше не важна.
- Из базового слоя убираются 35 `!important`; те, что относятся к оболочкам (радиусы пиксельных скинов), переезжают в `@layer skin`.
- Если правило обязано победить всё (например, `border-radius: 0` для пиксельного скина), оно живёт в `@layer skin` и применяется через `html.pixel-skin` — то есть может быть переопределено более поздним правилом того же слоя.
- Это снимает главную причину «CSS поехал»: больше не нужно угадывать специфичность.

### 2.3. Контракт: что скину можно

**Разрешено (paint):** `color`, `background`, `background-image`, `border*`, `border-radius`, `box-shadow`, `text-shadow`, `font*`, `letter-spacing`, `opacity`, `filter`, `backdrop-filter`, `outline`, `::-webkit-scrollbar*`, `::before/::after` у компонентов скина.

**Разрешено с оговоркой:** `transform` — только в `:active`/`:hover` на своём элементе, не более 2 px, без влияния на соседей.

**Запрещено:** `display`, `position`, `inset`, `width`, `height`, `min/max-*`, `margin`, `padding`, `gap`, `flex*`, `grid*`, `overflow`, `z-index` вне слоя декора, `content` с текстом интерфейса.

Если скину нужен другой отступ заголовка — это **токен контракта**, а не его CSS:

```css
/* базовый слой */
.sec-h h2 { padding: var(--skin-heading-pad, 0 0); margin-left: var(--skin-heading-ml, 0); }
/* скин задаёт только значения */
html.skin-retro { --skin-heading-pad: 3px 10px; --skin-heading-ml: -10px; }
```

Так «ретро-плашка заголовка» остаётся, но геометрию задаёт контракт.

### 2.4. Слоты и декор

В разметке — два слота, которые уже логично иметь:

```html
<div class="skin-slot" data-slot="bg" aria-hidden="true"></div>     <!-- фон: небо, горы, скан-линии -->
<div class="skin-slot" data-slot="chrome" aria-hidden="true"></div> <!-- планка окна, LCD, спектр -->
```

Правила:

- оба слота — `position: absolute; inset: 0; pointer-events: none; contain: strict; z-index: 0/2`;
- содержимое задаётся **только псевдоэлементами** скина (CSS), без вставки DOM;
- если нужен «живой» элемент (LCD, спектр), он объявляется в JS-карте `SKIN_DECOR` и вставляется **внутрь слота**, а не в поток; высота и позиция — из токенов (`--skin-chrome-h`);
- слот `bg` ограничен `.app-shell` с `overflow: hidden` — фон физически не может раздвинуть интерфейс.

Ошибка прошлого раза была именно в том, что декор вставлялся в `footer` и `.queue-col` — в поток. Слоты это исключают.

### 2.5. Геометрический аудит (точные правила)

Запуск: `npm run audit:geometry` (Playwright, тот же CDP, что у `audit:skins`).

Размеры: **900×600**, **1280×800**, **1600×1000**.

Проверки (только видимые элементы, `offsetParent !== null` и не `[hidden]`):

1. **Переполнение окна** — `rect.left < -1 || rect.top < -1 || rect.right > shell.right + 1 || rect.bottom > shell.bottom + 1`. Исключения: элементы внутри слота декора, `position: fixed`.
2. **Пересечение зон** — только для `header`, `main`, `footer`, `.queue-col`, `.results-col`: если прямоугольники пересекаются больше чем на 2 px по обеим осям.
3. **Обрезка текста** — только для элементов с `text-overflow: clip` и `white-space: nowrap`: `scrollWidth > clientWidth + 2`. Намеренный ellipsis не считается ошибкой.
4. **Мелкие кнопки** — `button`, `input`, `[role=button]` видимые: меньше 24×24 (кроме иконочных `.cbtn`, для них порог 20×20).
5. **Скролл-ловушки** — у `overflow: hidden` контейнеров `scrollHeight` не должен превышать `clientHeight + 4` (иначе содержимое недоступно).

Реальное окно проверяется отдельно: IPC-хук `test:setSize` (только в dev) вызывает `mainWindow.setSize(w,h)` и повторяет проверки — это ловит случаи, где `setViewportSize` ведёт себя иначе.

### 2.6. Визуальные эталоны

- Запуск на **моках** (`tests/ui/mock5.js`), сеть отключена: обложки — локальные заглушки.
- Инжект CSS в тесте: `* { animation: none !important; transition: none !important; caret-color: transparent !important; }`, `document.body.style.cursor = 'none'`.
- Ждём `document.fonts.ready`; DPR = 1.
- Маскируются: область `webview`, часы/время, полоса прогресса.
- Сравнение: **по регионам**, порог 0.5 % пикселей на регион и 1.5 % на весь экран; глобальное среднее не используется (иначе одна большая зона маскирует мелкие поломки).
- Эталон обновляется только флагом `--update-baseline` и попадает в дифф отдельным коммитом.

### 2.7. Док OBS

`/app.css` собирается из первого `<style>` (`src/main.js:509`). Решение: **скины не применяются к доку** — он остаётся нейтральным (как и задумано с темами Yami). Если позже понадобится — сервер будет отдавать `/app.css?skin=<id>` и конкатенировать блоки, но это отдельная задача.

## 5. Второй проход: что нашла проверка (факты, а не предположения)

1. **Подвал вне `.app-shell`.** При 1280×800: `.app-shell` = 696 px, `footer` = 104 px, сумма = 800. Значит геометрический аудит должен сравнивать с вьюпортом, а не с `.app-shell`. Первая версия правила давала ложные срабатывания на детях подвала — это уже воспроизведено.
2. **Вьюпорт ≠ окно.** `page.setViewportSize(900×600)` меняет `innerWidth` (раскладка пересчитывается), но `outerWidth` остаётся прежним — реальное окно Electron не меняется. Для честной проверки нужен dev-хук `mainWindow.setSize`, иначе тестируем только CSS-эмуляцию.
3. **Минимум окна — 900×600** (`main.js:682`), а не 980. Тестировать уже 900 бессмысленно: приложение не даст такое окно.
4. **`/app.css` для OBS-дока** собирается из **первого** `<style>` в `index.html` (`main.js:509–515`). Любой вынос скинов в отдельные файлы или во второй `<style>` до дока не доедет. Пока скины доку не нужны — фиксируем это как решение, а не как «забыли».
5. **`!important` в базовом слое сильнее скина.** В CSS-слоях `!important`-объявления более раннего слоя перебивают нормальные правила более позднего. Поэтому нельзя просто «запретить `!important`» — сначала надо убрать/перенести 35 существующих.
6. **Схемы нельзя грузить из JSON на `file://`.** `fetch('skin.json')` на `file://` блокируется, а окно может грузиться именно так (`main.js:701`). Схемы остаются в JS.
7. **Обложки и веб-вкладка нестабильны** между запусками: визуальные эталоны без мока и масок будут «мигать». Есть готовые моки (`tests/ui/mock5.js`, `mock7.js`) — их и надо использовать.
8. **Расширение `.queue-col` в пиксельных скинах**: проверено, что при 900×600 ничего не переполняется, базовый каркас держится. Значит фундамент можно менять аккуратно, не переделывая раскладку.

### Что из этого меняет план

- границы геометрии — вьюпорт, зоны: `header`, `main`, `footer`, `.queue-col`, `.results-col`;
- отдельный dev-хук для реального ресайза окна;
- минимальный тестовый размер — 900×600;
- решение по доку зафиксировано: скины к нему не применяются;
- порядок работ прежний, но шаг 1 (слои) начинается с инвентаризации 35 `!important`.
