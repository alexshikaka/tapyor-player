# План переработки системы скинов — версия 3

Версия 3 учитывает две независимые проверки: (1) сверку с кодом и эксперименты, (2) отдельное ревью «на злобу» по коду и удалённому коммиту. Обе нашли ошибки в предыдущих версиях. Ниже — исправленная картина.

---

## 1. Post-mortem: почему «поехали» Scorched Earth и Winamp

Причина не в `!important` и не в «войне каскада». По коммиту `449e2d9` видно две вещи:

1. **Декор вставлялся в поток.** `SKIN_DECOR` добавлял `.wa-lcd` через `prepend` в `footer`, а `.wa-spec` — в `.queue-col`. Оба были обычными flex-блоками с высотой и `margin-bottom` → занимали место и раздвигали раскладку.
2. **Скин резервировал место своими правилами.** `html.skin-scorch main { padding: 0 14px 92px !important; gap: 22px }`, `html.skin-winamp .qhead { padding: 3px 8px; margin: -1px -1px 8px }`, `.hrow1 { margin: 8px 12px 4px }`. При другом размере окна резерв не совпадал с содержимым — зоны налезали.

Обе оболочки и `SKIN_DECOR` удалены в `44aac3d`. В **текущем** коде раскладку трогает ровно одно правило оболочки: `html.skin-retro .sec-h h2 { padding: 3px 10px; margin-left: -10px }` (`src/index.html:1167`). Плюс `html.pixel-skin body { filter: … }` (`:1138`) — это paint, но `filter` создаёт containing block для всех `position: fixed` (модалки, контекстное меню, тосты).

**Задача плана — не «починить каскад», а не допустить повторения:** скину запрещено менять геометрию, а проверка должна это ловить.

## 3. Контракт скина

### 3.1. Слои вместо `!important`

```css
@layer base, skin, font, user;
```

- база → `base`, оболочки → `skin`, наборы `html.font-*` → `font`, пользовательские правки → `user`;
- между слоями порядок слоёв сильнее специфичности: `html.pixel-skin *` из `skin` бьёт `.row .more` из `base` без `!important`;
- **важно:** `!important` инвертирует приоритет слоёв, поэтому первый шаг — убрать 10 презентационных `!important` из базы, иначе они победят `skin`;
- сброс радиусов для пиксельных скинов переезжает в `@layer skin` (`html.pixel-skin * { border-radius: 0 }`) — без `!important`, но токенами это не заменить (25/208).

### 3.2. Что можно и нельзя

**Разрешено:** `color`, `background*`, `border*`, `border-radius`, `box-shadow`, `text-shadow`, `font*`, `letter-spacing`, `opacity`, `image-rendering`, `outline`, `transform` только в `:active` (не двигает поток), `::before/::after` своих компонентов, `::-webkit-scrollbar-*` **кроме** `width`/`height`.

**Запрещено:** `padding`, `margin`, `width`, `height`, `min/max-*`, `inset/top/right/bottom/left`, `display`, `flex*`, `grid*`, `gap`, `order`, `position` (кроме `relative` на своём компоненте), `zoom`.

**Запрещено на общих контейнерах** (`html`, `body`, `.app-shell`, `header`, `main`, `footer`, `.queue-col`, `.results-col`): `filter`, `backdrop-filter`, `transform`, `will-change`, `contain`, `perspective` — они меняют containing block и композитинг.

**Линт** (`tests/skins/lint.js`) проверяет **весь CSS проекта**, а не только `skins/*`: иначе 10 базовых `!important` обесценивают правило. Инлайновые стили `:1617/:1623/:1637` выносятся в классы до включения линта.

## 4. Где живут скины и как грузятся

- **Схемы остаются в JS** (`SKIN_SCHEMES` в `index.html`): загрузка манифеста через `fetch` на `file://` невозможна, а схемы читаются синхронно при старте (`loadSkinSchemes` до `applySkin`).
- **CSS скинов — отдельные `<style data-skin-style="<id>">`** в `index.html` на первом этапе. Вынос в `skins/<id>/skin.css` — отдельный шаг, потому что `/app.css` для OBS-дока собирается только из первого `<style>`; после выноса док получит базу без скинов (сейчас это осознанное решение: док нейтральный).
- **Без мигания:** анти-FOUC держится на инлайн-скрипте и инлайн-`<style>`. Внешний `<link>` так не умеет → либо все скины остаются инлайном, либо подключаются все сразу через `<link media="not all">` с переключением `media`. Динамическая подгрузка по требованию даёт кадр базовой темы.
- **Кеш:** `Cache-Control: no-store` для CSS уже стоит — не трогать.

## 5. Раскладка и слоты

### 5.1. Режимы

- `default` — как сейчас.
- `compact` — `@media (max-width: 1100px)`: `main` становится колонкой, очередь уезжает под контент. Единственный режим, который можно добавить без переноса разметки.
- `frame` (рамка окна вокруг контента) **откладывается**: `footer` лежит **вне** `.app-shell` (`:1722` закрывает shell, `:1738` — footer), для рамки его надо переносить внутрь. Это отдельная задача, не «настройка скина».

### 5.2. Слоты

| Слот | Хост | Свойства | Резерв |
|---|---|---|---|
| `bg` | `body::before` у скина | `fixed; inset:0; z-index:0; pointer-events:none` | нет |
| `frame-top` | `.app-shell`, первый child | `absolute; top:0; left/right:0; height:var(--frame-top)` | `--frame-top` у приложения |
| `frame-bottom` | `.app-shell`, последний | то же снизу | `--frame-bottom` |
| `hud` | `header` | `absolute; pointer-events:none; -webkit-app-region:no-drag` | нет (оверлей) |
| `side` | `.queue-col` | `absolute; inset:0 0 auto 0; contain:layout paint` | `--queue-top` |
| `overlay` | `body`, ниже модалок | `fixed; inset:0; z-index:40; pointer-events:none` | нет |

Правила:

- `pointer-events:none` обязателен: `header` имеет `-webkit-app-region: drag` (`:43`) — оверлей без этого сломает перетаскивание окна.
- `contain: layout paint`, **не** `strict`: `strict` добавляет size-контейнмент и обрежет фаски/тени.
- `.app-shell` не имеет `position` (`:38`) — слот `absolute` внутри него уедет в viewport, пока не задан `position: relative`; это надо сделать в базе, а не в скине.
- `z-index` слотов ниже модалок (60/100/250); существующие оверлеи CRT/ретро `9998/9999` (`:1089`, `:1146`) пересмотреть, иначе они перекрывают диалоги.
- 12 столбиков спектра в псевдоэлементы не влезают: либо `repeating-linear-gradient` в одном псевдоэлементе, либо отдельный «живой» элемент в слоте `side` с резервом `--queue-top`.
- Всё, что занимает место (LCD, спектр), **обязано** иметь резерв в раскладке приложения (`--queue-top`, `--frame-*`). Абсолютный блок без резерва = перекрытие.

## 6. Геометрические проверки (заменяют «на глаз»)

Матрица: **900×600**, 1280×800, 1600×1000; DPR = 1.

Перед прогоном: сбросить пользовательские размеры — `queue-col.style.cssText=''`, `video.style.height=''`, `aspectRatio=''`, настройки `queueWidth`/`videoHeight`.

1. **«Не влезло»**: `body.scrollHeight > body.clientHeight + 1` или `appShell.scrollHeight > appShell.clientHeight + 1`. Это ровно тот симптом, что был у Winamp.
2. **Пересечения — только сиблинги:** `[header, main, footer]` и внутри `main` — `[.results-col, .splitter, .queue-col]`. Оба прямоугольника `width>0 && height>0`, `display != none`, площадь пересечения `> 2px²`. Вложенность (`.queue-col` внутри `main`) проверять нельзя — она даст вечное «пересечение».
3. **Обрезка текста** — только белый список «обязано влезать» (`nav button`, `.cbtn`, `.pbtn`, `.tm`, `.qhead span`, `.f-meta .t`), при `text-overflow: clip`, `-webkit-line-clamp: none`, нет `title`/`aria-label`. Намеренный ellipsis (`.row .t`, `.row .s`, `.col-head .hint`, `.skin-c b`, `.vmeta .t`) не проверяется.
4. **Клик-таргет**: `button, a, input, select, [role=button]`, видимые; `min(w,h) ≥ 20 && max(w,h) ≥ 24`; иконочные без текста — порог 18×18. Исключение: `.upd-check` (19×22), `.hwarn`.
5. **Скрытые вкладки**: `[hidden] { display:none !important }` даёт rect 0×0 — пропускать всё с нулевой площадью.
6. **Реальное окно** дополнительно проверяется dev-хуком `test:setSize` → `mainWindow.setSize`: `page.setViewportSize` меняет CSS-раскладку (`innerWidth`), но реальное окно не трогает (`outerWidth` остаётся прежним — проверено).
