# Сборка релиза: обязательный регламент

> Триггер: владелец говорит **«собери релиз на гитхаб»** (или «делай релиз»).
> Дальше модель выполняет всё ниже **без напоминаний**. Если какой-то пункт невозможен — пишет об этом и **не публикует**, пока владелец не решит.

Регламент один для всех моделей: Claude Code, DeepSeek, любая другая.

## 0. Перед началом

- [ ] Подтвердить версию (например, `0.19.1`) и состав изменений.
- [ ] `git status` чистый; всё нужное закоммичено.
- [ ] Понять, из какой ветки релиз (`experiment`) и как она соотносится с `main`.

## 1. Код и проверки

- [ ] `node --check` для `src/main.js` и последнего `<script>` в `src/index.html`.
- [ ] `npm run audit:skins` — все оболочки, 0 ошибок.
- [ ] Живой прогон: запуск, очередь, волна, окно масштаба (открыть/закрыть/сменить тему), подсказки, счётчик заказов, скины, масштаб 60/100/140.
- [ ] Проверка раскладки на 900×600 и 1280×800.
- [ ] Для каждой проверки — команда, результат, скриншот.

## 1.5. Аудит перед релизом

- [ ] Провести аудит по `docs/AUDIT.md` — минимум проходы 1–2, плюс прицельно проверить всё, что менялось в этой версии.
- [ ] Отчёт положить в `docs/audits/ГГГГ-ММ-ДД-модель.md`.
- [ ] Копию отчёта включить в снимок: `docs/releases/vX.Y.Z/AUDIT.md`.
- [ ] Critical/High либо исправить, либо явно записать в отчёте, почему сознательно оставлены.
- [ ] Если аудит не делался — релиз не готов (см. Definition of Done).

## 2. Документы версии

Создать `docs/releases/vX.Y.Z/`:

- [ ] `README.md` — что за версия и что читать.
- [ ] `CHANGES.md` — изменения простым языком, без жаргона.
- [ ] `DECISIONS.md` — решения этой версии (из `docs/DECISIONS.md`).
- [ ] `ERRORS.md` — что ломалось и как починили (из `docs/ERRORS.md`).
- [ ] `VERIFICATION.md` — как проверяли: команды, замеры, скриншоты.
- [ ] `SESSION.md` — дайджест переписки и ссылки на ассеты.
- [ ] `docs/` — копии `HANDOFF.md`, `DEV.md`, `CHECKS.md` на момент релиза.
- [ ] `AUDIT.md` — отчёт аудита перед релизом.
- [ ] `MANIFEST.json` — версия, дата, коммит, тег, хеши файлов.

Обновить:

- [ ] `docs/releases/INDEX.md` — строка о новой версии.
- [ ] `docs/CURRENT.md`, `docs/HANDOFF.md`, `TODO.md`.
- [ ] `docs/CHECKS.md` — чек-лист приёмки для владельца.

## 3. История и переписка

- [ ] В момент релиза заново выгрузить историю командой `npm run history:export` (только на ПК владельца, где есть журнал DSH; на другой машине журнала нет — используется уже лежащая в репозитории история и архив).
- [ ] Собрать `history/DIGEST.md` и `history/FULL.md` — **в zip для ассетов**, не в git.
- [ ] Добавить/проверить карточки всех сессий с прошлого релиза в `docs/sessions/`.
- [ ] Подхватить старые архивы (например, `Documents\tapyor-handoff`) в `history/archive-<год-месяц>/` или ассет.
- [ ] Проверить, что в истории нет значений ключей (см. раздел «Секреты»).

## 4. Версия и сборка

- [ ] Поднять версию в `package.json`.
- [ ] Собрать установщик локально и проверить запуск.
- [ ] Проверить `latest.yml` и что автообновление увидит новую версию.
- [ ] Коммит «X.Y.Z: …».

## 5. Публикация (только по команде)

- [ ] Слить `experiment` → `main` (или перенести нужные коммиты), проверить конфликты.
- [ ] Прогнать проверки уже на `main`.
- [ ] Поставить тег `vX.Y.Z`, запушить `main` и тег.
- [ ] Дождаться сборки GitHub Actions, проверить релиз: установщик, `latest.yml`, `.blockmap`, описание.
- [ ] Приложить ассеты: `history-FULL-vX.zip`, `history-archive-*.zip`, `shots-vX.zip`.
- [ ] В описании релиза — ссылка на `docs/releases/vX.Y.Z/README.md`.

## 6. После релиза

- [ ] Проверить обновление с предыдущей версии на ПК владельца.
- [ ] Обновить `docs/CURRENT.md` и `HANDOFF.md` (версия, дата).
- [ ] Добавить карточку сессии релиза.
- [ ] Если что-то пошло не так — удалить тег/релиз, откатить версию, зафиксировать в `docs/ERRORS.md`.

## Definition of Done

Релиз считается сделанным, только если **все** пункты верны:

1. Тег `vX.Y.Z` и релиз на GitHub существуют.
2. Установщик скачивается и запускается.
3. `docs/releases/vX.Y.Z/` заполнена целиком, включая `AUDIT.md`.
4. `history/COMPACT.md` обновлён, полная история приложена ассетом.
5. Карточки сессий есть за весь период с прошлого релиза.
6. `CURRENT.md`, `HANDOFF.md`, `TODO.md`, `INDEX.md` обновлены.
7. В репозитории и ассетах нет значений ключей.
8. Владелец получил короткий отчёт: что вышло, где лежит, что проверить.

Если хотя бы один пункт не выполнен — это не релиз, а черновик. Модель обязана сказать об этом прямо.

## Секреты

- Перед пушем прогнать поиск по шаблонам: `GOCSPX-`, `github_pat_`, `ghp_`, `AIza`, `xox`, `password`, `Bearer`.
- Значения ключей заменять на `<REDACTED_…>` в истории и документах.
- Секреты живут только в GitHub Secrets / Яндекс Облаке / Google Cloud, не в файлах.
- Если GitHub заблокировал push из-за секрета — не «разрешать» секрет, а вычищать.

## Старые версии

- Полных снимков до 0.19.0 не существует; не выдумывать.
- Для старых версий — `docs/releases/ARCHIVE.md` с уровнями A/B/C и ссылками на источники.
- Если у владельца есть старые выгрузки чатов — приложить их ассетом, а не пересказывать.

| Проверки | делает | смотрит скриншоты |
| Документы | заполняет | — |
| История | собирает | — |
| Сборка | делает | проверяет установщик |
| Публикация | делает после «делай релиз» | даёт команду |
