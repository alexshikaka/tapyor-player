# Релизы и обзоры

Точка входа для модели, которая впервые видит проект: начни с последней версии, затем живые документы.

**Прошлые версии (0.5–0.18)** — `docs/releases/ARCHIVE.md`: таблица с уровнями полноты и ссылками на источники. Полных снимков у них нет, и это честно помечено.

## Порядок чтения

1. `docs/releases/INDEX.md` (этот файл) — какая версия последняя.
2. `docs/releases/vX.Y.Z/README.md` — обзор версии: что нового, решения, ошибки, проверки.
3. `docs/HANDOFF.md` — текущее состояние (может быть новее последнего релиза).
4. `docs/DEV.md` — как запустить на ПК.
5. `docs/DECISIONS.md`, `docs/ERRORS.md` — почему так и где грабли.
6. `TODO.md` — полная хронология, если нужен контекст.

## Как оформляется снимок

При подготовке релиза создаётся папка `docs/releases/vX.Y.Z/` по шаблону:

```
README.md      — вход и порядок чтения
CHANGES.md     — изменения простым языком
DECISIONS.md   — решения этой версии
ERRORS.md      — что ломалось и как починили
VERIFICATION.md— как проверяли: команды, замеры, скриншоты
SESSION.md     — дайджест переписки + ссылки на ассеты GitHub
MANIFEST.json  — commit, tag, дата, версия, хеши
docs/          — копии HANDOFF/DEV/CHECKS на момент релиза
```

Полные стенограммы и архив скриншотов прикрепляются к GitHub Release как ассеты, а не коммитятся в репозиторий.
