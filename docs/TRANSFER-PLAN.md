# План передачи проекта между моделями (простыми словами)

Представь эстафету: каждая модель пробегает свой отрезок и передаёт следующей **палочку** — папку `docs/` в репозитории. В ней написано всё: что сделано, почему, где грабли и что дальше. Переписка — это приложение к палочке, а не сама палочка.

## 1. Что теперь всегда есть в проекте

```
docs/START-HERE.md     ← первое, что читает любая модель
docs/CURRENT.md        ← «где мы сейчас»: кто работал, что дальше
docs/HANDOFF.md        ← полное состояние и карта кода
docs/DEV.md            ← как запустить на твоём ПК
docs/DECISIONS.md      ← почему сделано так
docs/ERRORS.md         ← где уже набили шишки
docs/sessions/         ← карточки сессий: одна сессия = один файл
docs/releases/         ← снимки версий и архив прошлых
```

Это не отчёты «для галочки». Это ровно то, что новая модель читает вместо твоей памяти.

## 2. Что делаешь ты

**Перед переключением** — ничего. Всё уже лежит в репозитории.

**При переключении** — открываешь Claude Code и пишешь:

> Привет. Мы работали над «Тапёром» с другой моделью. Прочитай `docs/START-HERE.md` и всё, на что он ссылается, чтобы войти в курс. Ничего не публикуй и не меняй версию без моей команды.

Всё. Дальше модель сама читает папку и задаёт вопросы, если чего-то не хватает.

**Если работаешь без GitHub** — отдаёшь архив `tapyor-handoff.zip` и те же слова. Но лучше через репозиторий: там свежее.

## 3. Что делает любая модель (в том числе Claude Code)

В начале:
1. Читает `START-HERE.md` → `CURRENT.md` → `HANDOFF.md` → `DEV.md` → `DECISIONS.md` → `ERRORS.md` → последний снимок релиза.
2. Проверяет, что поняла: как запустить, что за версия, какие правила.

В конце сессии (это обязанность, а не пожелание):
1. Обновляет `docs/CURRENT.md` — дата, что сделано, что дальше.
2. Добавляет карточку `docs/sessions/ГГГГ-ММ-ДД-модель.md`.
3. Дописывает `TODO.md`; решения — в `DECISIONS.md`, ошибки — в `ERRORS.md`.
4. Если менялся запуск — правит `DEV.md`.
5. Выгружает переписку: краткий дайджест в репозиторий, полную — в ассеты релиза (или в архив).

Правило: **сессия не считается законченной, пока нет карточки и обновлённого `CURRENT.md`**.

## 4. Как это выглядит по шагам

### Шаг 1. Сейчас (сделано)
Точка входа, журналы решений и ошибок, карточки сессий, архив версий, стратегия. Ничего не опубликовано.

### Шаг 2. До релиза (пока работаем мы с тобой)
- Каждая сессия заканчивается карточкой и обновлением `CURRENT`.
- `TODO.md` пополняется по ходу.
- Переписка выгружается в `E:\tapyor-handoff` (дайджест + полная версия).

### Шаг 3. Релиз 0.19.1
- Собирается снимок `docs/releases/v0.19.1/` (обзор, изменения, решения, ошибки, проверки, манифест).
- Полные стенограммы и скриншоты прикрепляются **к GitHub Release** (ассеты), а не коммитятся в репозиторий.
- Ставится тег, обновляется `docs/releases/INDEX.md`.
- Проверка: новая модель по папке отвечает на 5 вопросов (как запустить, что нового, почему окно масштаба отдельное, что не делать, что дальше).

### Шаг 4. После релиза
Каждая следующая версия повторяет шаг 3. Старые снимки не редактируются — история важнее красоты.

### Шаг 5. Если переключение случилось до релиза
Ничего страшного: модель пишет карточку в `docs/sessions/`, обновляет `CURRENT`, коммитит. Этого достаточно, чтобы следующая подхватила.

## 5. Где хранится переписка

| Что | Где | Зачем |
|---|---|---|
| Краткий дайджест (запрос → суть) | `history/COMPACT.md` в репозитории | чтобы модель прочитала за один раз |
| Подробный дайджест | ассет релиза (`history-DIGEST.zip`) | если нужен контекст решений |
| Полная стенограмма | ассет релиза (`history-FULL.zip`) | для поиска конкретного места |
| Карточки сессий | `docs/sessions/` | быстрый обзор по датам |

В репозиторий не кладём мегабайты: git должен оставаться лёгким. Полные выгрузки — в ассеты.

## 6. Особенности Claude Code

- Claude Code читает файлы репозитория — этого достаточно, `START-HERE.md` для него обычный файл.
- Свою переписку Claude Code хранит у себя; нам не нужно её разбирать. Важно, чтобы он **сам** написал карточку сессии и обновил `CURRENT.md` по нашему шаблону.
- Если он не умеет выгружать свою стенограмму — не страшно: карточка + `TODO.md` + `DECISIONS.md` дают 90 % пользы; полную стенограмму можно приложить вручную.

## 7. Безопасность

- В репозиторий не попадают токены, cookies, `settings.json`, личные пути.
- Если репозиторий публичный — полные стенограммы в ассеты **не прикладывать** или предварительно вычищать.
- Скриншоты — только окно приложения.

## 8. Что может пойти не так и что делаем

| Риск | Как страхуемся |
|---|---|
| Модель забыла карточку | в `START-HERE` это первый пункт обязанностей; `CURRENT` без даты — сигнал |
| Документы устарели | `CURRENT` — главный; в конце сессии обязательное обновление |
| Репозиторий раздулся | полные стенограммы только в ассетах |
| Публичный репозиторий и личные данные | проверка перед публикацией, вычистка |
| Модель не поняла проект | приёмка «слепой моделью» по 5 вопросам |

## 9. Итог одной фразой

Ты переключаешь модель одной фразой «прочитай `docs/START-HERE.md`», а каждая модель оставляет после себя карточку сессии и обновлённый `CURRENT.md`. Переписка и решения едут рядом — в репозитории и ассетах релиза.
