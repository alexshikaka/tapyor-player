# Аудит оболочек

Проверяет, что после правок интерфейса оболочки не «потеряли» элементы:
находит всё, что выпало из оформления кожи.

## Запуск

```bash
npm run audit:skins            # все оболочки, сводка
node tests/skins/audit.js --skins=crt   # только одна
node tests/skins/audit.js --verbose     # все находки, а не первые 8
node tests/skins/audit.js --json        # машинный вывод
```

Нужен `playwright-core` и установленный Chrome/Edge:

```bash
npm i -D playwright-core
set CHROME_PATH=C:\Program Files\Google\Chrome\Application\chrome.exe
```

Код выхода: `1` — есть ошибки, `0` — только предупреждения и информация.

## Что проверяется

| Проверка | Уровень | Смысл |
|---|---|---|
| **Углы** | ошибка | в оболочке все скругления должны быть 0; ненулевое — элемент выпал из кожи |
| **Шрифт** | ошибка | текст должен идти шрифтом оболочки (разрешённые семейства читаются из её же правил) |
| **Хром** | предупреждение | структурная панель с фоном должна иметь фаску или ореол, иначе выглядит «плоской» |
| **Палитра** | инфо | плотная заливка должна быть из цветов оболочки, а не жёстко зашитой в коде |

## Как он это понимает

Аудит не хранит список классов руками. Он читает CSS-правила самой оболочки
(`html.pixel-skin …`, `html.skin-… …`) и вытаскивает из них:

- какие **классы** оболочка уже оформляет (из селекторов);
- какие **шрифты** объявлены (из `font-family`);
- какие **цвета** объявлены (из hex/rgb в правилах).

Дальше он обходит все видимые элементы на каждой вкладке и сравнивает их
вычисленные стили с этим набором. Появился новый компонент — аудит сам скажет,
что он не попал в оболочку, без правки теста.

## Что делать с находками

- **ошибка «углы/шрифт»** — почти всегда inline-стиль или новый класс, которому нужен сброс; правится в CSS оболочки;
- **«панель без фаски»** — добавьте класс в правило фаски (`html.pixel-skin .card, …`);
- **«цвет вне палитры»** — замените жёсткий цвет на переменную (`var(--acbg)` и подобные) или добавьте цвет в палитру кожи.
