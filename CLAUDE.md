# Тапёр — инструкция для ИИ-помощника

**Порядок входа:** `docs/START-HERE.md` → `docs/CURRENT.md` → `docs/HANDOFF.md` → `docs/DEV.md` → `docs/DECISIONS.md` → `docs/ERRORS.md`. Для аудита — `docs/AUDIT.md`, для релиза — `docs/RELEASE-CHECKLIST.md`.
На GitHub есть только main (релиз и документы). Рабочая ветка experiment — локально у владельца; если её нет, работай в main.

## Кто владелец и как с ним работать

- Владелец — русскоязычный стример, **не программист**. Общаться по-русски, простыми словами, без жаргона. Часовой пояс — Киев (UTC+3).
- Тапёр — бесплатный музыкальный плеер для ПК (Electron, Windows). Цель — полноценный плеер с уникальной функцией (много площадок в одном окне + заказы зрителей), не просто помощник для стрима.
- Владелец проверяет сборки сам и присылает лог (Настройки → Программа → «Скопировать лог») и JSON самопроверки.

## Жёсткие правила

1. **Собирать установщик только по команде** «собери» / «собирай» / «СОБИРАЮ» или явной просьбе собрать. Коммит и push без сборки — можно и нужно.
2. **Сначала макет, потом код** для заметных изменений интерфейса (если владелец не сказал «делай всё сразу»).
3. **Безопасность:** никогда не читать и не доставать сохранённые пароли браузеров. Вход — только через официальные окна/OAuth. Тапёр не хранит пароли. Cookies/ключи — только вставленные самим пользователем, хранятся зашифрованно (safeStorage), никогда не пишутся в лог.
4. Не менять `appId` (`app.alexshikaka.tapyor`) и внутреннее имя пакета `tapyor` — иначе у пользователей перестанут приходить обновления (с 0.13.0; до этого были `app.shikaka.streamplayer` / `stream-player`, сменены, пока программа была только у владельца). Папка данных закреплена в `main.js` (`pinUserData`: «Плеер для стрима», «stream-player», «Тапёр») — её не трогать.
5. Каждое изменение — коммит в рабочую ветку (`experiment` — локально у владельца; если её нет в клоне, создай от `main`) с понятным русским сообщением + запись в `TODO.md`.
6. В конце сессии обязательно: обновить `docs/CURRENT.md`, добавить карточку `docs/sessions/ГГГГ-ММ-ДД-модель.md`, дописать `TODO.md`; решения и ошибки — в `docs/DECISIONS.md` и `docs/ERRORS.md`. Сессия не закончена без карточки и `CURRENT.md`.

## Репозиторий и сборка

- GitHub: `alexshikaka/tapyor-player` (раньше `shikaka068091/stream-player`, старый адрес редиректит).
- Версия — в `package.json`. Перед сборкой поднять версию (0.11.0 → 0.11.1 / 0.12.0).
- Сборка релиза — только по команде владельца и по `docs/RELEASE-CHECKLIST.md`; локальный запуск — `docs/DEV.md`. Пользователи получают обновление через electron-updater (кнопка «Обновить до …» в шапке).
- Проверить релиз: `gh api repos/alexshikaka/tapyor-player/releases/tags/vX.Y.Z` (GraphQL у `gh` в облачных сессиях Claude закрыт — только REST через `gh api`).
- Установщик: `Tapyor-Setup-X.Y.Z.exe` (с 0.13.0). Латиницей программа везде называется **Tapyor**.
- npm-реестр в облачных сессиях может быть закрыт — Electron локально не запустить. Интерфейс проверяется в Chromium через Playwright с поддельным `window.app` (см. «Тесты»).

## Устройство (src/)

| Файл | Что делает |
| --- | --- |
| `main.js` | Главный процесс Electron: окна, настройки (`DEFAULTS`), IPC, yt-dlp, источники, самопроверка, горячие клавиши, обновления, CORS для медиа |
| `index.html` | Весь интерфейс (~7,5 тыс. строк, один `<script>`): поиск, очередь, плеер, плейлисты, настройки, браузер |
| `rank.js` | Порядок выдачи поиска: точность, доступ к площадке, «для эфира», склейка версий одной песни (`window.TapRank`, работает и в Node) |
| `preload.js` | Мост `window.app` между интерфейсом и главным процессом |
| `yandex.js` | API Яндекс Музыки (поиск, потоки, волна, лайки, плейлисты) |
| `deezer.js` | Справочник Deezer (без ключа): дискография исполнителя, треклисты альбомов — для страницы исполнителя |
| `lastfm.js` | Last.fm: описание, теги, слушатели, похожие (ключ `src/lastfm.json` из секрета `LASTFM_API_KEY` при сборке) |
| `theme.js` | Темы: из 5 основных цветов строит все CSS-переменные (OKLCH, контраст), варианты палитр по направлениям, код темы `TAPYOR1:` (`window.TapTheme`, работает и в Node) |
| `reqparse.js` | Заказы со стрима: какие песни искать в сообщении доната (`plan`), вердикт «точно/сомнение» (`judge`), пометки спорных (`flags`). Работает в Node и в окне (`window.TapReq`). Проверки: `node tests/reqparse/judge.js`, `node tests/reqparse/plan.js` |
| `donations.js` | Сервисы донатов: DonationAlerts (OAuth, порт 47219), DonatePay, Donatello — опрос, «уже показанные», ключи в safeStorage |
| `sitepage.js` | Сайт-визитка стримера и QR для OBS; выкладка в репозиторий `tapyor-page` на GitHub стримера |
| `match.js` | Разбор строк «Исполнитель — Название» для «Плейлиста из текста» и замены трека |
| `ymweb.js`, `ymweb-preload.js` | Запасной путь Яндекса: сайт music.yandex.ru в скрытом окне, Тапёр нажимает «Слушать» |
| `ytauth.js`, `ytoauth.js` | Вход в YouTube: ключ из браузера (cookies) и OAuth (ждёт `src/google-oauth.json`) |
| `recipes.js`, `recipes.json` | «Рецепты» сайтов (селекторы, регулярки). Тапёр подтягивает свежий `recipes.json` с GitHub `main` — правка чинит сайт без новой версии (поднимать `"version"`) |
| `vendor/hls.min.js` | hls.js 1.5.17 для SoundCloud (HLS) |

Ключевые идеи:
- **Источники:** `ym` Яндекс, `yt` YouTube, `sc` SoundCloud, `bc` Bandcamp (по ссылкам), `au` Audius, `tap` — свои плейлисты Тапёра. Карта `SRC` в `index.html`.
- **Звук:** без Web Audio. Громкость элемента = `curVol * el._fade * el._norm`. Ровная громкость — по r128 Яндекса (`lufs`), только приглушение. Плавный переход — два `<audio>` (aud/aud2). **Не ставить `crossOrigin`** на медиа: это ломало потоки Яндекса (0.10.1).
- **Запасные пути:** `getStream` → `withFallback` → YouTube iframe (`ytx`) / сайт Яндекса (`ymx`) / тот же трек на другой площадке (`failOver` + `findAlt`).
- **Самопроверка:** `runHealth` в `main.js`; результат в настройке `health` и в логе по шагам; значок ⚠ в шапке.
- **Плейлисты Тапёра** хранятся в настройке `savedLists` (элементы с `src:'tap'` содержат `tracks`; остальные — сохранённые ссылки на чужие плейлисты).
- Оформление: цвета в CSS — переменные (`--bg0…--bg4`, `--ln…`, `--tx…`, `--ac`, `--pri`, `--hov`); темы: `violet` (по умолчанию), `mono` (`html.theme-mono`), свои `c:<id>` (`html.theme-custom` + `theme-light`, переменные в style корня; список — настройка `themes`, цвет полосы окна — `themeBar`; localStorage `tapTheme`/`tapThemeVars` для мгновенного применения). Новые цвета писать только через переменные.
- Настройки поиска: `searchMode` (`smart|exact|subs|free|air|src`), `srcOrder`.

## Тесты

`tests/ui/run.sh` — Playwright-проверки интерфейса (нужны python3 и playwright с Chromium). Скрипт делает ссылку `app2 → ../../src`, генерирует тестовые звуки и прогоняет `t9…t12`:
- t9 — SoundCloud/Audius, HLS, замена битого трека;
- t10 — самопроверка (запуск на паузе);
- t11 — громкость и плавный переход;
- t12 — поиск по исполнителю, варианты выдачи, плейлисты, настройки поиска;
- t13 — карточка исполнителя → «Все треки», итог вставки ключа YouTube, крестик;
- t14 — страница исполнителя (Яндекс, Deezer, Last.fm), альбом Deezer с поиском песен, Telegram/адресная строка во вкладке «Браузер»;
- t15 — подсказки после Enter, кнопка «Назад» в выдаче, вкладка «Поиск» на странице исполнителя;
- t17 — тема «Монохром»: переключение, сохранение;
- t19 — редактор тем: создать, цвет, подбор вариантов (свой + The Color API), светлая, код, импорт, удалить/вернуть;
- t18 — стартовый чеклист: открыт/свёрнут, проблемы, ⚠, автопочинка, проверка отправки отчёта;
- t23 — вкладка «Заказы»: пометки, итог, «все точные», другой вариант, авторежим, «не хватает суммы», настройки «Стримерам», сайт (mock_req.js);
- t16 — плитки с длинными названиями не вылезают и не накладываются (1440 и 1000 px).

Поддельный `window.app` — `mock5.js` / `mock7.js` (+ `ov8.js` для поиска). Ошибки `ERR_TUNNEL_CONNECTION_FAILED` и 404 в выводе — нормальны (нет интернета/обложек).
Также: `node --check src/main.js`, и проверка синтаксиса скрипта в `index.html` (вырезать `<script>` и `node --check`).

## Проверки и отчёты

- Быстрая проверка при запуске — `quickCheck` в `main.js` (IPC `qc-run`, события `qc-item`), чеклист в окне поиска — `renderQC` в `index.html`. Глубокая — `runHealth`. Автопочинка — IPC `auto-fix`.
- Отчёты об ошибках — `sendReport` в `main.js` → Yandex Cloud Functions (`REPORT_URL`, код в `server/yc-report`, задеплоен владельцем) → GitHub Issues с меткой `fp-<отпечаток>`. При исправлении закрывать задачу с меткой `fixed-in-X.Y.Z`.

## Ключи и секреты

Ключи сервисов не хранятся в git (GitHub блокирует секреты в открытом репозитории). Они лежат в секретах репозитория (Settings → Secrets and variables → Actions), сборка пишет их в файлы: `GOOGLE_OAUTH_JSON` → `src/google-oauth.json`, `LASTFM_API_KEY` → `src/lastfm.json`, `DA_CLIENT_ID` + `DA_CLIENT_SECRET` → `src/da.json` (DonationAlerts), необязательный `GH_OAUTH_CLIENT_ID` → `src/github-oauth.json` (вход в GitHub по коду для сайта-визитки). Из облачной сессии Claude секреты не задать — владелец добавляет их сам на сайте GitHub.

## Передача между моделями

Проект ведётся по очереди разными моделями. В конце каждой сессии:

1. Обновить `docs/CURRENT.md` — что сделано, что дальше.
2. Добавить карточку `docs/sessions/ГГГГ-ММ-ДД-модель.md`.
3. Дописать `TODO.md`; решения и ошибки — в `docs/DECISIONS.md` и `docs/ERRORS.md`.
4. Переписку сдать: краткую — в `history/COMPACT.md`, полную — в архив/ассеты.

## Релиз

Только по фразе «собери релиз на гитхаб». Выполнить `docs/RELEASE-CHECKLIST.md` целиком и без напоминаний, затем `node tools/release-preflight.mjs <версия>`. Если чек-лист не выполнен — сказать прямо, что релиз не готов, и не публиковать.
